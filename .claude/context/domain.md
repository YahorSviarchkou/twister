# Domain

Repair workshop for personal light vehicles (bikes, kick scooters, e-scooters): a customer brings a vehicle, the front desk accepts it, a mechanic diagnoses it, the customer approves an estimate, the work is done (possibly waiting for parts), an invoice is issued, the customer pays and takes the vehicle.

## Current model (`tw-core`)

- `Customer` (name parts, phone, email, bikes), `Transport` (the vehicle: type, brand, model, year; to become `Vehicle` in `...domain.vehicle`).
- References: `Country`, `SpareBrand`, `SpareType`, `TransportBrand`, `TransportType`, `ServiceType` (price list), `Spare` (with warehouse quantity and price).
- `RepairOrder` → one `RepairTask` → many `RepairTaskItem` (service type + list of spares, no quantity); `RepairInvoice` (diagnostic, spare and labour prices, no total or status).
- Status is the latest row of a per-entity status history.

## Current statuses (`tw-workflow`)

- Order: OPEN → ACCEPTED → WAITING_PAYMENT → CLOSED; REJECTED from OPEN or ACCEPTED.
- Task: CREATED → DIAGNOSIS → IN_PROGRESS → READY; CANCELED.
- Item: CREATED → (WAITING_PARTS) → IN_PROGRESS → READY; CANCELED.

## Known gaps

No diagnostic report, no estimate approval, no spare quantity per item, no payment entity, invoice never generated by the workflow. Accepted model: ADR 0005 and `../../tw-docs/diagrams/state-order.mmd`.

## Vertical boundary

Vehicle-specific code lives in `...domain.vehicle`; the vehicle type (bike, kick scooter, e-scooter) is reference data. Order, work item, state machine, stock and billing code and their use cases must not import that package (ArchUnit test); vehicle use cases live in their own `vehicle` packages; the order refers to the vehicle only by `SubjectId`. No generic asset abstraction until a different vertical exists. See ADR 0005.

## Vocabulary

| Term | Meaning |
|---|---|
| Front desk | Person who accepts and hands over vehicles, takes payment |
| Mechanic | Person who diagnoses and repairs |
| Work item | One job on an order: a service plus parts |
| Estimate | Proposed work items and price after diagnosis, needs customer approval |
| Service book | Repair history of one vehicle |
| Vehicle | A bike, kick scooter or e-scooter brought for repair; its type is reference data |
