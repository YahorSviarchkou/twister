# Internationalisation

Goal: a new UI language (for example Georgian) is a language pack, a jar with property files and optionally a font, added as a dependency. No code changes.

- Every user-facing text is a message key: FXML `%key`, code through `MessageSource`, document templates through the same messages. No literals in UI code.
- Each module keeps its own bundle under `i18n/<module>/messages*.properties`; the base file `messages.properties` is English. The message source collects all bundles found on the classpath (`classpath*:i18n/**/messages*.properties`), so a language pack only adds files.
- The list of languages in settings is built from the bundles found, never from an enum or a hard-coded list.
- Enums and statuses are shown through keys (`order.status.READY`), never through `name()` or `toString()`.
- Messages with numbers use ICU plural syntax, so languages with other plural rules need no code changes.
- Dates, numbers, money and phone numbers are formatted with the selected `Locale`, never with fixed patterns in code.
- Layouts must not depend on text length: no fixed widths for labels and buttons.
- Printed documents embed their fonts; a language pack whose script the default font lacks ships its own font and registers it.
